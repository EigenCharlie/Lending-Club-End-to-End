                                                                                      When using WOE predictors, depending on the
                                                                                      dataset size, we can encounter a problem with a
                                                                                      shift in the intercept value in logistic model*

                                                                                      As we add more predictors, due to a joint
                                                                                      optimization of intercept and feature weights
                                                                                      with maximum likelihood, we can see that the
                                                                                      resulting model’s intercept will veer away from
                                                                                      the true value that we observe in univariate WOE
                                                                                      binning summaries (correct by default)

                                                                                      A practitioner needs to carefully examine the
                                                                                      intercept value and perform corrections in case
                                                                                      the baseline is incorrect → use prior prevalence
                                                                                      correction or enforce the fixed value of intercept

Regression vs. Classification
The misunderstood link between logistic regression and classification

In machine learning, regression usually refers to the
task of predicting a numeric (continuous) target
variable. However, the term can also describe a
specific family of parametric models used for this
purpose (e.g., linear regression, generalized linear
models).

Logistic regression is one such regression model, a
Generalized Linear Model (GLM), that models the
log-odds of the target class. Although it is a
regression algorithm, it is widely used for
classification tasks because its outputs can be
interpreted as probabilities of belonging to a class,
just like other classification algorithms.
                                                        Many classification algorithms produce soft scores, continuous values
In other words, logistic regression outputs a
                                                        that can be interpreted as probabilities (e.g., logistic regression,
continuous score between 0 and 1, which we can          gradient boosting). These scores are then converted into hard class
interpret as a probability and then convert into some   labels by applying a decision threshold. Some algorithms, however,
hard class decision (e.g., approve vs. decline).        only produce hard labels. This is why the general term is classification.

Decision Trees, Bagging, and Random Forests
“Random selection of features to split each node that compares favorably to Adaboost”

                                               Random Forests, introduced by Leo Breiman in 2001, are
                                               a powerful ensemble method that extends the idea of
                                               bagging (1996). They build many decision trees on
                                               bootstrapped samples of the training data and then
                                               combine their predictions:

                                               • Randomization: At each split, only a random subset of
                                                 features is considered.
                                               • Aggregation: Predictions from all trees are averaged
                                                 (for regression) or combined by majority vote (for
                                                 classification).
                                               • Performance: Random Forests require minimal tuning,
                                                 handle high-dimensional data well, and provide robust
                                                 generalization.

                                               Breiman described Random Forests as “the combination
                                               of many unpruned decision trees, each constructed on a
                                               random subset of the data and features, whose results are
                                               averaged to form the final prediction.”

 “… when boosting came out much later,
 Rob and Trevor and I tried to show what it was doing,

LogitBoost Implementation in Python
From theory to code

                                      import numpy as np
                                      from sklearn.base import BaseEstimator, ClassifierMixin
                                      from sklearn.tree import DecisionTreeRegressor
                                      from sklearn.metrics import log_loss
                                      from scipy.special import expit as sigmoid

                                      class LogitBoost(BaseEstimator, ClassifierMixin):
                                          def __init__(self, n_iter=100, learning_rate=1.0, max_depth=1):
                                              self.n_iter = n_iter
                                              self.learning_rate = learning_rate
                                              self.max_depth = max_depth
                                              self.predictors = []
                                              self.loss_dict = []

                                          def fit(self, X, y):
                                              # Initialize weights
                                              w = np.ones(X.shape[0]) / X.shape[0]
                                              # Initialize predictions
                                              F = np.zeros(X.shape[0])

                                              for _ in range(self.n_iter):
                                                  # Working response and weights
                                                  p = sigmoid(F) # probability
                                                  z = (y - p) / (p * (1 - p)) # working response
                                                  w = p * (1 - p) # case weights

                                                  # Fit a regressor (stump) to the working response
                                                  tree = DecisionTreeRegressor(max_depth=self.max_depth)
                                                  tree.fit(X, z, sample_weight=w)
                                                  self.predictors.append(tree)

                                                 # Update F
                                                 F += self.learning_rate * tree.predict(X)
                                                 return self

Gradient Boosting – Gradient Boosted Decision Trees
Fitting residuals iteratively with weak learners

                                                                            GBDT are a gradient boosting implementation, where a
                                                                            decision tree is used as a “weak learner”. This means
                                                                            that although each individual tree may be only slightly
                                                                            better than a random guess, a joint ensemble of such
                                                                            trees will generate an accurate prediction.

                                                                            GBDT models work sequentially: we start with an initial
                                                                            prediction (e.g., log-odds of event rate for classification)
                                                                            and work with residuals iteratively using regression
                                                                            trees.

                                                                            The idea is that each new tree is trying to predict the
                                                                            residuals of a predecessor and, as a result, the sum of
                                                                            predictions will approximate the observed outcome.

                                                                            Instead of using gradient descent to estimate
                                                                            parameters (e.g., linear weights in logistic regression),
                                                                            we use gradient descent to estimate log-likelihood in a
                                                                            functional space.

XGBoost – Hyperparameter Effects
Regularization and probability calibration




   XGBoost offers several parameters that allow to impose regularization constraints during training. They are
   documented on a relatively high level, and their behavior is not so widely explained. Among these are:
   • Gamma (𝛾): “pseudo-regularization” parameter influencing how XGBoost prunes tree branches to minimize
     model complexity
   • Alpha (α): L1 (Lasso) regularization parameter of leaf weights, helping the model to focus on a subset of leaf
     weights
   • Lambda (λ): L2 (Ridge) regularization parameter of leaf weights acting a smoothing mechanism to prevent large
     leaf weights

   import numpy as np                                                          binary:logistic
   import xgboost as xgb

   # Set XGBoost parameters
   params = dict(
       objective="binary:logistic", max_depth=1, base_score=0.5,
   )
   params_log_raw = dict(
       objective="binary:logitraw", max_depth=1, base_score=0.0, #logit(0.5)
   )
   def loglikelihood(preds, train_data):
       eps = 1e-16
       labels, preds = train_data.get_label(), 1.0 / (1.0 + np.exp(-preds))    binary:logitraw
       grad, hess = preds - labels, preds * (1.0 - preds)
       hess[hess < eps] = eps
       return grad, hess

   params_log_loss = dict(
       max_depth=1, base_score=0.0, disable_default_eval_metric=1,
   )

   # Train the XGBoost model

   xgb_clf_raw = xgb.train(params_log_raw, dtrain, num_rounds)
   xgb_clf_ll = xgb.train(
     params_log_loss, dtrain, num_rounds, obj=loglikelihood
   )

From XGBoost trees to logistic regression
Tree leaves as embeddings

                                                                             One common technique to convert a gradient-
                                                                             boosted decision tree model to a linear model (with
                                                                             non-linearly transformed inputs) is to use one-hot-
                                                                             encoding for the boosted trees’ leaf indices.


                                                                             The trick here for learning non-linear transformations
                                                                             is to bin the feature and treat the bin index as a
                                                                             categorical feature (He et al. 2014).


                                                                             With this approach, we treat each individual tree as a
                                                                             categorical feature that takes as value the index of
                                                                             the leaf an instance ends up falling in.


                                                                             This allows to linearize the boosted tree models and
                                                                             even treat them in the credit scoring framework.




Enhancing Robustness of Gradient-Boosted Decision Trees through One-Hot Encoding and Regularization (link).

The Changing Role of Statistics in the Age of Computing: Why Statisticians Lost to AI and
Machine Learning (according to J. Friedman)

 Jerry Friedman makes a powerful point about how the computer
 revolution reshaped statistics (2001). In the past, data collection
 was costly, so statisticians focused on carefully designed
 experiments.

 • Data collection used to be expensive → careful experiment
   design.

 • The computer revolution made data cheap and abundant.

 • Each 10× leap in tech forces us to rethink methods.

 • We [statisticians] are no longer the only game in town.

 Much earlier, in the 1950s, D.J. Finney wrote to R.A. Fisher about
 computing. For Fisher, the computer should be a tool to check
 whether approximations were accurate, not a substitute for
 scientific thinking. He feared that if scientists simply handed data
 over to machines, they risked becoming servants of the machine
 rather than interpreters of their own hypotheses.
