Why combine WOE and Logistic Regression? Lessons from Spiegelhalter-Knill-Jones method Using Weight of Evidence (WOE) as inputs assumes that the variables are independent of one another (within each outcome class), which is unrealistic in many applied settings. To allow for this the Spiegelhalter-Knill-Jones (1984) method calculated "adjusted weights of evidence," which are obtained by entering the raw weights of evidence as independent variables in a logistic regression equation. Credit scorecards picked up this method around 1980-1990s by moving from dummy variables to WOE transformation for categorical data. D. Hand (Hand & Henley, 1997) notes that weight of evidence transformation was becoming increasingly common in the 1990s. Logistic regression fitted on WOE inputs can still be seen as Naive Bayes classifier, where each WOE term is re-weighted to account for feature dependencies and maximize likelihood. According to D. Spiegelhalter, one of the authors of this system, mentions that this approach also increases the calibration accuracy of scoring. Statistical and Knowledge-Based Approaches to Clinical Decision-Support Systems, with an Application in Gastroenterology (link). https://rss.onlinelibrary.wiley.com/doi/abs/10.2307/2981737

Pitfalls of using WOE with Logistic Regression Tips to avoid producing wrong models Coefficient sign flips Sometimes we face a situation when one of the variables in WOE form flips its sign in the logistic regression fit. Why does this happen? Usually, it is caused by one of the predictors carrying the same information as other variables, thus “reversing” the correct relationship with the target variable. Some ways to mitigate this is: • perform more granular feature selection based on Gini / IV → isolate and drop the problematic feature and choose a better one • Perform more robust feature engineering to identify the strongest signal in the data Coefficients without the extra feature Coefficients with the extra feature Sign flip

Logistic Model Trees (link). In machine learning, regression usually refers to the task of predicting a numeric (continuous) target variable. However, the term can also describe a specific family of parametric models used for this purpose (e.g., linear regression, generalized linear models). Logistic regression is one such regression model, a Generalized Linear Model (GLM), that models the log-odds of the target class. Although it is a regression algorithm, it is widely used for classification tasks because its outputs can be interpreted as probabilities of belonging to a class, just like other classification algorithms. In other words, logistic regression outputs a continuous score between 0 and 1, which we can interpret as a probability and then convert into some hard class decision (e.g., approve vs. decline). Many classification algorithms produce soft scores, continuous values that can be interpreted as probabilities (e.g., logistic regression, gradient boosting). These scores are then converted into hard class labels by applying a decision threshold. Some algorithms, however, only produce hard labels. This is why the general term is classification. Random Forests (link). Random Forests, introduced by Leo Breiman in 2001, are a powerful ensemble method that extends the idea of bagging (1996). They build many decision trees on bootstrapped samples of the training data and then combine their predictions: • Randomization: At each split, only a random subset of features is considered. • Aggregation: Predictions from all trees are averaged (for regression) or combined by majority vote (for classification). • Performance: Random Forests require minimal tuning, handle high-dimensional data well, and provide robust generalization. Breiman described Random Forests as “the combination of many unpruned decision trees, each constructed on a random subset of the data and features, whose results are averaged to form the final prediction.” Decision Trees, Bagging, and Random Forests “Random selection of features to split each node that compares favorably to Adaboost” https://link.springer.com/article/10.1023/A:1010933404324

LogitBoost Implementation in Python From theory to code import numpy as np from sklearn.base import BaseEstimator, ClassifierMixin from sklearn.tree import DecisionTreeRegressor from sklearn.metrics import log_loss from scipy.special import expit as sigmoid class LogitBoost(BaseEstimator, ClassifierMixin): def __init__(self, n_iter=100, learning_rate=1.0, max_depth=1): self.n_iter = n_iter self.learning_rate = learning_rate self.max_depth = max_depth self.predictors = [] self.loss_dict = [] def fit(self, X, y): # Initialize weights w = np.ones(X.shape[0]) / X.shape[0] # Initialize predictions F = np.zeros(X.shape[0]) for _ in range(self.n_iter): # Working response and weights p = sigmoid(F) # probability z = (y - p) / (p * (1 - p)) # working response w = p * (1 - p) # case weights # Fit a regressor (stump) to the working response tree = DecisionTreeRegressor(max_depth=self.max_depth) tree.fit(X, z, sample_weight=w) self.predictors.append(tree) # Update F F += self.learning_rate * tree.predict(X) return self https://github.com/deburky/calibration/blob/44ffbfedbb42a73d5147642f1780994d4ff4247d/loss-functions/logistic-boosting.ipynb

Gradient Boosted Decision Trees [Guide]: a Conceptual Explanation (link). Gradient Boosting – Gradient Boosted Decision Trees Fitting residuals iteratively with weak learners GBDT are a gradient boosting implementation, where a decision tree is used as a “weak learner”. This means that although each individual tree may be only slightly better than a random guess, a joint ensemble of such trees will generate an accurate prediction. GBDT models work sequentially: we start with an initial prediction (e.g., log-odds of event rate for classification) and work with residuals iteratively using regression trees. The idea is that each new tree is trying to predict the residuals of a predecessor and, as a result, the sum of predictions will approximate the observed outcome. Instead of using gradient descent to estimate parameters (e.g., linear weights in logistic regression), we use gradient descent to estimate log-likelihood in a functional space. https://neptune.ai/blog/gradient-boosted-decision-trees-guide

In the past, data collection was costly, so statisticians focused on carefully designed experiments. • Data collection used to be expensive → careful experiment design. • The computer revolution made data cheap and abundant. • Each 10× leap in tech forces us to rethink methods. • We [statisticians] are no longer the only game in town.
