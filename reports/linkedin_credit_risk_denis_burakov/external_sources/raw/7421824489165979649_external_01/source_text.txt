About us
MLflow is an open-source platform for managing the complete machine learning lifecycle, including experimentation, reproducibility, deployment, and a central model registry. MLflow supports both traditional ML and generative AI workflows:
- MLflow Tracking: Record and query experiments, including code, data, config, and results. Now with integrated tracing for GenAI workflows across multiple frameworks.
- MLflow Models: Deploy machine learning models in diverse serving environments, with GenAI support for ChatModels and streaming interfaces.
- Model Registry: Store, annotate, discover, and manage models in a central repository.
- MLflow Evaluation: Evaluate model performance using customizable metrics, including LLM-as-judge frameworks and GenAI-specific benchmarks.
- MLflow Deployments: Simplify model deployment and serving across various platforms, with expanded capabilities for hosting large language models.

Tried out #MLflow 3.12.0. A few notes for anyone using it!
1. The multimodal tracing change is the one that actually matters to many. Storing images/audio/PDFs as artifact attachments instead of inline binary means trace payloads stop bloating...
anyone who's traced an agent handling screenshots knows inline base64 makes traces slow to load and inspect.
The new mlflow-attachment:// URI with UI rendering is a sensible fix, and they shipped attachment size limits and rendering guards alongside it :) .
2. Codex, Gemini, and Qwen coding-agent tracing got added next to the existing Claude Code integration. Useful if you're on those agents.
3. Two things technical users should not miss, because they're not in the headline bullets:
* enable_mlserver is deprecated in the pyfunc serving backend. If you serve via MLServer, plan around this.
* Async trace logging is now on by default for OSS MLflow.
Overall: a focused observability release. Worth upgrading if you do agent/LLM work ; but read the breaking change before you do .

OpenHands agents run on their own—they edit files, run terminal commands, and browse the web—but there is no structured record of what happened or whether the result was good.
MLflow connects through OpenTelemetry: you set three environment variables so OpenHands traces go to your MLflow server (where to send traces, which experiment to use, and the trace transport format).
You get every large language model call and tool step in MLflow, can evaluate runs with built-in judges like RelevanceToQuery and Correctness, and can route model traffic through AI Gateway for budget control and usage tracking.
